## 3. Login rules

### Required scopes

```javascript
const SCOPES = ["username", "payments", "wallet_address"];
```

| Scope | Why |
|---|---|
| `username` | Show the pioneer username |
| `payments` | Required for U2A and incomplete-payment handling |
| `wallet_address` | Needed to send the one-time Get Pi A2U payment |

### Login rules for SARAVIA Testnet

- Login is **Pi only**. No email, password, Google, Apple, or Stripe login on this build.
- First visit: show **Continue with Pi**.
- Call `Pi.authenticate(SCOPES, onIncompletePaymentFound)` only after the user taps the button.
- Send `accessToken` to your backend. Do not trust client-side `user` data alone.
- Backend must call `GET https://api.minepi.com/v2/me` with header `Authorization: Bearer <accessToken>`.
- Create the app session only if `/me` succeeds.
- Store `uid`, `username`, and `wallet_address` in your database.
- `uid` is per-app. If the user revokes permission, they get a new `uid`.
- Logout only clears **your** session cookie/JWT. It does not disconnect Pi Network.
- If the SDK is missing (`!window.Pi`), show: `Open this app in Pi Browser to sign in.`
- After login, immediately run incomplete-payment recovery.

### Login implementation

```javascript
async function piLogin() {
  if (!window.Pi) {
    throw new Error("Open SARAVIA in Pi Browser to sign in.");
  }

  const auth = await window.Pi.authenticate(
    ["username", "payments", "wallet_address"],
    onIncompletePaymentFound
  );

  const res = await fetch("/.netlify/functions/pi-me", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ accessToken: auth.accessToken })
  });

  const session = await res.json();
  if (!res.ok) throw new Error(session.error || "Login verification failed");
  return session; // { uid, username, wallet_address }
}

function onIncompletePaymentFound(payment) {
  fetch("/.netlify/functions/pi-complete", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      paymentId: payment.identifier,
      txid: payment.transaction && payment.transaction.txid
    })
  });
}
```

Backend `/me` check:

```text
GET https://api.minepi.com/v2/me
Authorization: Bearer <accessToken>
```

## 5. One-time “Get Pi” (A2U)

Purpose: send Test-Pi **once** from the SARAVIA Testnet app wallet to the logged-in pioneer.

### Product rules

- Button label: **Get Pi**
- Amount: `0.1` Test-Pi (change if you want)
- Memo: `SARAVIA Testnet welcome bonus`
- Eligible only after successful Pi login
- One claim per `uid`
- If already claimed, disable the button: `Already claimed`
- Credit the user only after Pi returns a completed A2U payment
- Never expose the app wallet seed to the browser

### Server flow

1. Verify session from `/me`.
2. Reject if `claims[uid]` already exists.
3. Create A2U payment with Platform API:

```text
POST https://api.minepi.com/v2/payments
Authorization: Key <PI_API_KEY>
Content-Type: application/json
```

```json
{
  "amount": 0.1,
  "memo": "SARAVIA Testnet welcome bonus",
  "metadata": { "type": "welcome_bonus", "once": true },
  "uid": "<pioneer_uid>"
}
```

4. Submit the payment with the app wallet seed on the server (never in frontend).
5. Complete the payment with the blockchain `txid`.
6. Mark `uid` as claimed so it cannot run again.

Frontend only calls your function:

```javascript
async function claimGetPi() {
  const res = await fetch("/.netlify/functions/pi-get-pi", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ accessToken })
  });
  return res.json();
}
```

Suggested Netlify function: `netlify/functions/pi-get-pi.js`.

Persist claims in a store you control (Supabase, Fauna, or a locked JSON/DB). Memory-only storage resets on each deploy and would allow a second claim.

## 6. User-to-App payments (U2A)

Use this for bookings, support, or feature unlocks on Testnet.

```javascript
function payApp(amount, memo, metadata) {
  return window.Pi.createPayment(
    { amount, memo, metadata },
    {
      onReadyForServerApproval: async (paymentId) => {
        await fetch("/.netlify/functions/pi-approve", {
          method: "POST",
          headers: { "Content-Type": "application/json" },
          body: JSON.stringify({ paymentId })
        });
      },
      onReadyForServerCompletion: async (paymentId, txid) => {
        await fetch("/.netlify/functions/pi-complete", {
          method: "POST",
          headers: { "Content-Type": "application/json" },
          body: JSON.stringify({ paymentId, txid })
        });
      },
      onCancel: (paymentId) => console.log("canceled", paymentId),
      onError: (error, payment) => console.error(error, payment)
    }
  );
}
```

Backend:

```text
POST https://api.minepi.com/v2/payments/{paymentId}/approve
Authorization: Key <PI_API_KEY>

POST https://api.minepi.com/v2/payments/{paymentId}/complete
Authorization: Key <PI_API_KEY>
{ "txid": "<txid>" }
```

You already have `pi-approve.js` and `pi-complete.js`. Keep them reading `process.env.PI_API_KEY` only.

Unlock the booked feature only after `/complete` returns success.

Example first Testnet payment: amount `0.1`, memo `SARAVIA Testnet support`.

## 7. Backend functions required on Testnet

| Function | Role |
|---|---|
| `pi-me` | Verify access token, return uid/username/wallet |
| `pi-approve` | Approve U2A payment |
| `pi-complete` | Complete U2A payment |
| `pi-cancel` | Cancel / mark cancelled payments |
| `pi-get-pi` | One-time A2U Get Pi + claim lock |

Every function must:

- Use `Authorization: Key ${process.env.PI_API_KEY}`
- Check `process.env.PI_NETWORK === "testnet"`
- Refuse to run if the API key is missing
- Never return the wallet seed
